# scafo - Agent Guide

`scafo` is a self-hosted, multi-tenant serverless deployment platform for JS apps. Its JSON registry lives in an S3-compatible bucket and is mutated with CAS conditional writes; it has no database or consensus protocol. One binary is both node daemon and CLI.

## Ask first

Ask before acting when intent is ambiguous. For design or product decisions, run a short structured Q&A: numbered questions, 2–4 concrete labeled options, a marked recommendation, then synthesize and confirm decisions before implementation.

## Boundaries

- A Scafo fleet is one installation: one registry and its Scafo nodes. A Scafo node is a machine running `scafo sail`.
- The unit scafo deploys, places, serves, blocks, retires and deletes is an **application**, identified by its **name**: a slug of 1-63 lowercase alphanumerics separated by single hyphens, the same rule Celld applies to a config's `name`. One application is one Celld fleet and one current deployment, and it is served at `<name>.<platform domain>`. A Scafo node may supervise one Celld node process per assigned application. Unqualified `fleet` and `node` mean Scafo's machine-level concepts; name Celld's process-level concepts explicitly.
- Scafo requires Celld 0.5.0: `scafo sail` runs `celld --version` before it opens the bucket and refuses an older or unreadable binary with `capability-missing`, and each node record carries the `versions` (Scafo and Celld) its daemon booted with. A node does not start an application's process, and does not accept a deploy for it, while another live node serving that application reports a Celld version it may not share a fleet with (`version-skew`, 409); an upgrade freezes deploys first, then stops every node of the installation, unless the two releases are a rolling pair upstream declared and `_celld-contract.ts` lists (`ROLLING_CELLD_RELEASES`, never inferred from version numbers), in which case nodes are replaced one at a time. Celld owns deployment adoption, application health, cells, and runtime resource policy; Scafo owns registry, auth, placement, supervision, deploy intake, and the routing every ingress reads.
- Celld exposes one current deployment per application fleet. Scafo records a monotonic deployment revision, not a selected version; it has no per-deployment host or local version selection. See https://github.com/denoland/celld/issues/181.
- Vocabulary follows Celld: a **deployment** is what Celld serves, identified by its **version**; a **deploy** is one run of `scafo deploy`; a **build** is compiling only (esbuild, the image, `pnpm build`).
- Container classes are Celld's, end to end: Scafo starts no container, probes no engine and gates nothing. A node's Celld processes find the engine socket themselves (`DOCKER_HOST` is handed through when the daemon has it), and `celld deploy` on the node that accepts a deploy builds the image through the engine client the image ships, so that node needs the engine too. Mounting a socket is the operator's opt-in, and it makes the node root-equivalent on that machine. Run with Celld 0.5.0: rootful Docker through Scafo end to end, and rootful Podman with Celld alone, in both cases with Celld in the engine host's network namespace — on the machine itself, or as a container on the host network. Anything else is unsupported until Celld supports it, as Kubernetes is. Operators place such applications with node labels and selectors.
- `/.well-known/scafo/health` is served by the node/API listener; `/.well-known/celld/health` is served on application hosts. `scafo health` probes the former at the listener it resolves from the daemon's own sources (env and config file, not `sail` flags); it is the image's HEALTHCHECK.

## Commands

- `pnpm build`, `pnpm compile [linux-amd64|linux-arm64]`, `pnpm test`
- `pnpm vitest run test/utils.test.ts`, `pnpm typecheck`, `pnpm lint`, `pnpm fmt`
- `node dist/cli/index.mjs sail --help`
- `pnpm scale:real` — an on-demand benchmark on real containers (`--help` for its flags), never run in CI and asserting no budget: it sweeps emulated machine sizes and store latencies so a default is chosen from the slowest profile it holds on, not from one big development machine.

The ordinary integration suite starts an S3 store with testcontainers. Set `SCAFO_TEST_STORE=seaweedfs|rustfs`, or supply `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, and `S3_BUCKET`.

Docker E2E is opt-in; absent Docker skips a suite, not a product failure. A run builds `dist/` once, before any suite starts (`test/integration/_global-setup.ts`); no suite builds for itself and every node container bind-mounts the worktree read-only, so several suites may share one command and run in parallel. Run `docker build --target probe -t scafo-probe .` once (the node host the suites mount the build into). Use `vitest.no-store.config.ts`; these suites own their containers. `test/integration/e2e-containers.test.ts` also needs the host's engine socket at `/var/run/docker.sock` and skips without one; it starts a real container and answers from inside it.

- `SCAFO_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e.test.ts` — Caddy, deploy adoption, OIDC, retirement.
- `SCAFO_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-traefik.test.ts` — Traefik pull provider.
- `SCAFO_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-multinode.test.ts` — replicas, selectors, durable cells, failover, drain, reassignment.
- `SCAFO_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-image.test.ts` — non-root image, bundled tools, healthcheck, shutdown.
- `SCAFO_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-tls.test.ts` — TLS storage, locks, and auth.
- `SCAFO_E2E=1 SCAFO_E2E_ROLLING_IMAGE=scafo-probe-celld-0.5.0 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-rolling.test.ts` — a rolling Celld upgrade, one node replaced at a time, across a pair `ROLLING_CELLD_RELEASES` lists. The second image carries the other release of the pair: copy the Dockerfile outside the repo, point its Celld `FROM` at that release's tag and digest, and `docker build -f <copy> --target probe -t scafo-probe-celld-0.5.0 .` from the worktree.
- `SCAFO_K3S_E2E=1 pnpm vitest run --config vitest.no-store.config.ts test/integration/e2e-k3s.test.ts` — real manifest, default Traefik, placement, drain, two-pod recovery; requires privileged containers.
- `pnpm vitest run test/integration/store.test.ts` — bucket conformance against the `SCAFO_TEST_STORE` matrix (seaweedfs, rustfs).

## Placement of work

- `src/core/**` holds runtime-agnostic contracts, registry, auth, and pure placement logic.
- `src/drivers/**` implements runtime seams; `src/daemon/**` and `src/cli/**` assemble them.
- Internal files use a leading `_`. `examples/` is production-shaped; `playgrounds/` is disposable. Keep both executable and self-contained.

## Architecture and security

- All registry mutation uses `CasStore` preconditions. Surface conflicts as `ScafoError("cas-conflict")`; retrying callers re-read before writing. The store driver repeats a write the store answers with a transient error and raises `ScafoError("store-unavailable")`—503—once the tries run out, and a lease or lock refused by its own precondition is re-read before it is called lost. Lease-gated work is judged by the TENANCY it was handed — the node and the fence — never by the record's version: the coordinator renews on its own timer while a deletion it carries out is still walking an application, and only a new acquisition, which moves the fence, ends a tenancy.
- Keep core pure where practical and on Web APIs; `unjwt` in `core/auth` and `unsecure` where external text is parsed or a random value is drawn are the exceptions. `Math.random` is used nowhere: every draw — a port, a backoff's jitter, an id — comes from `unsecure/random`, behind a seam a test can fix. Put runtime work behind core interfaces in drivers; add external runtime dependencies to `build.config.ts`.
- Token failures—bad, expired, forged, replayed, or unknown-key—are `ScafoError("auth-invalid")`. `trust-mismatch` remains the distinct authorization refusal. Its detail echoes only what the token itself said and ends with the `scafo trust add` command that admits exactly that subject — never the subjects already trusted, which any workload of a shared issuer could otherwise read, and no command at all for a subject carrying a glob, a quote or whitespace. `scafo trust set` states an issuer's whole subject list, `scafo trust add` keeps it and appends, each `--subject` is one subject (the flag repeats; nothing is split on commas), and every edit of a policy is a CAS update of the policy as stored.
- External text becomes an object through `unsecure` only—registry documents, request bodies, tokens, access logs, config and artifact files carry no key an object answers for on its own, and a config setting is read from a key the file itself holds. One rule refuses those names wherever variables are written: `scafo deploy --var` and `runtime.celldEnv` alike.
- Operators and nodes use separate keyspaces and cannot share an id. Admin and operator roles differ; operator-tier keys are application-scoped: a scope entry is `*` (all), an exact name, or a PREFIX GLOB — a run of name characters, which may end in a hyphen, followed by one trailing `*`, so `shop-*` reaches `shop-preview` and not `shop`. `*` anywhere else is `invalid-input`. A missing scope grants nothing. Bucket credentials remain fleet-root authority.
- Placement is selectors, rendezvous hashing, then replica count. Scafo neither infers nor reserves host resources; operators set runtime policy through Celld and the host/container platform via `runtime.celldEnv`, `--celld-env`, or `SCAFO_CELLD_ENV`. Scafo adds no Celld policy defaults.
- Bound deploy intake by archive size and entries, output tail, active/queued tasks, staged bytes, and receive/queue/task deadlines. These are scheduling bounds, not runtime admission.
- A deploy id is `<application>.<16 hex>`, and every state it moves through is a registry record under that application: any node answers a poll—the application in the id is what authenticates the caller—and a restart of the accepting node loses nothing. A record that reaches `deployed` names the deployment it produced by version, a failed record keeps the code of the error that failed it, and the CLI exits with it. A `celld deploy` that ends badly is `publish-failed` (502) with Celld's own output as the detail, whatever the cause; `invalid-input` is what Scafo itself refused before publishing. A failure with no code of Scafo's is the node's own `internal` (500) — in a deploy record and on the wire alike — and a refusal that follows a publish keeps its code. The coordinator's reaper fails a non-terminal record whose node stopped answering and deletes terminal ones after 7 days.
- A NODE READS WHAT CHANGED, NOT WHAT EXISTS. `_scafo/changes.json` holds `{v,token}`: a 16-hex token rewritten with a BLIND put (no precondition, last writer wins, fifty concurrent deploys never contend) by the `CasStore` decorator every registry context is built with, after a successful write under `_scafo/applications/`, `_scafo/placement/` or `_scafo/domains/`. It is a HINT — losing one costs latency, bounded by the resync interval, never correctness — so a hint that fails to write is logged and swallowed, and a mutation is never reported as failed because of one. Node records are not hinted (a heartbeat rewrites one every 30s); a node arriving, draining, or changing what it SERVES mints a token explicitly. Each node keeps ONE registry view (`src/core/registry/view.ts`), shared by the reconcile loop, the coordinator and deploy intake: it reads the hint once a pass — one GET, and nothing else when the token has not moved and no timer is up — and otherwise lists the kinds that could have moved and GETs only the records whose `listEntries` ETag differs from the cached one. `CasStore.listEntries` therefore returns an `etag` per entry in the form `get`/`put` answer with, and a listing that carries none is `store-nonconforming`. A refresh that fails keeps the previous view and throws: a registry that could not be read is never "every application was removed". `registry.resyncIntervalMs` (60s) is the bound on a lost hint; `registry.nodeRefreshIntervalMs` (30s) re-reads liveness, which is the AGE of a heartbeat and which no write announces. Operator routes still read the bucket directly — an operator asks rarely and must see the truth — with bounded concurrency rather than a serial loop. The coordinator's assignment pass is SKIPPED outright when neither the applications (their replicas, selectors, retired and blocked state), their placements, nor the live node set changed since the last completed pass: rendezvous hashing over the same inputs can only decide the same thing. The reaper takes ONE listing of `_scafo/deploys/` for the whole installation and caches records by ETag for the life of the coordinator — a terminal deploy never moves again, so a second sweep reads none of them. `GET /v1/deploys/:id` judges a non-terminal deploy whose node stopped answering at READ time, answering `failed`/`deploy-timeout` without writing; the sweep records the same judgement later. The budgets all of this is held to live in `test/scale/baseline.test.ts`, and `pnpm scale` prints them beside what the same installation cost before.
- After a publish the accepting node asks its LOCAL runtime process to adopt now — `POST /reload` on the process's internal listener, behind the runtime driver seam, bounded to a few seconds — and every other node serving the application does the same on the pass that sees the deployment revision move. A reload that fails is one line in the log: Celld's own 30s pointer poll is the fallback, and nothing depends on it having happened. There is no new route and no new record.
- A node takes 64 queued deploys, 4 of them for any one application, one publishing at a time, and is still bounded by `deploy.stagedBytes`. `scafo deploy` retries `deploy-overloaded` honouring the node's `retry-after`, with jittered backoff, until `--queue-timeout` (default 600s, the node's own queue deadline) has passed, printing one line when it starts waiting and one when it is admitted; `--no-wait` fails at once. A retry re-SENDS the staged artifact rather than re-packing it.
- Registry keys are flat and kind-prefixed, one prefix per kind, so listing one kind never reads another's keys and a listing of `_scafo/applications/` is one key per application—the listing every node runs on every reconcile pass. `_scafo/applications/<name>.json` is the application record, `_scafo/trust/<name>.json` its OIDC policy (which may exist BEFORE the application—an admin pre-grants a name and the first deploy creates it), `_scafo/deployments/<name>/<version>.json` and `_scafo/deploys/<name>/<id>.json` its history, `_scafo/placement/<name>.json` its placement, `_scafo/domains/<host>.json` a custom-domain claim, and `fleets/<name>/` is Celld's own keyspace. Every per-application prefix is listed with its trailing separator, so `shop` never reaches `shop-preview` or `shop2`. There is no create command and no create route: the first deploy creates the application, every other setter refuses a missing one with `not-found`, and every mutation is a functional CAS update that preserves the fields it does not own—a deploy can never drop `blocked` or `labels`. A CLAIM IS ONE HOST, INSTALLATION-WIDE, AND THE FIRST ONE WINS: `POST`/`DELETE /v1/applications/:name/domains/:host` claim and release it, an OPERATOR whose scope reaches the application makes both (a workload token never can), and a host another application holds is `reference-held` (409) whose detail names that application only to a caller whose scope reaches it too. The claim key and the mirror on the record are written referent-first, so a crash between them is repaired by re-running the claim; a release only ever drops a claim the named application holds, and anything else is `not-found`. A claimed host is lowercased and must be fully qualified—at most 253 characters, at least two labels of 1-63 `[a-z0-9-]` not starting or ending with a hyphen, the last label not all digits, and no wildcard, port, scheme, path, trailing dot or underscore (`invalid-input` naming the rule, `normalizeCustomDomain`); a host equal to or under a platform domain is refused too, because those name applications. One application holds at most `MAX_APPLICATION_DOMAINS` (64) of them, a blocked application takes no claim (releasing stays open), and a retired one does both.
- AN ACKNOWLEDGED WRITE IS NEVER LOST, and with more than one node that costs a NAME and a DIRECTORY, both derived and neither operator-settable (`runtime.celldEnv` refuses all three, as it refuses every name the driver writes). Celld's default durability acknowledges a write once a PEER holds it on its follower disk, before the bucket has it; a node recovers those writes at boot by taking over the log of its PREDECESSOR OF THE SAME NAME, and serves its own retained follower disk to the peers doing the same. So each supervised process gets `CELLD_NODE` = this Scafo node's id (one process per application per node and one Celld fleet per application, so the id is unique in that fleet and the same on every boot of the machine; `NODE_ID_RE` is deliberately narrower than the names Celld admits, which `test/node-name.test.ts` proves), `CELLD_WATCH` = `<state dir>/celld/<application>/work` and `CELLD_ASSET_CACHE_DIR` = `<state dir>/celld/<application>/assets` — upstream would otherwise pick a random name per start, a work directory under `$TMPDIR` new on every start, and one asset cache shared by every Celld process of the machine. The directories are created 0700 before the process starts. `<state dir>/celld/<application>/` is KEPT through every stop — retirement, blocking, reassignment, a drain, a daemon restart — because the disk may hold writes a peer still needs and the application may come back here; it is removed only by the reconcile pass that finds the application gone from the registry, never while a process for it runs on this node, and never on a pass whose registry read failed (`planLocalStateRemoval` decides, the runtime driver removes, and a directory that will not go is a reconcile failure and is retried).
- A PORT BELONGS TO AN APPLICATION FOR AS LONG AS THE NODE KNOWS IT. Celld ignores the `Host` header, so whichever process holds a port answers everything sent there, and the routing every ingress reads is rendered from node records peers re-read on a timer of their own: a port changing hands while anything still routes to it is one application's requests answered by another application's process. So each application's public and internal ports are chosen ONCE per node and kept at `<state dir>/celld/<application>/ports.json`, written atomically and 0600, reused on every later start — after a process exit, a daemon restart, a container re-created on the same state volume — which is what makes a node's `serving` record still correct after a restart. Both ports are drawn independently AT RANDOM from `runtime.portRangeStart`-`runtime.portRangeEnd` — never `public + 1`, so no stale public port names an internal listener — never one another application of the node holds, and only after a real bind-and-close probe on `runtime.bindHost`, because the range is the node's by convention and anything on the machine may be listening in it. A pair is released only by the pass that removes the application's local state, into a quarantine at `<state dir>/celld/.released.json` (`runtime.portQuarantineMs`, 10 minutes, pruned as entries age out and surviving a restart) that keeps it from every OTHER application until nothing can still be routing there. A persisted pair the probe finds taken does not wedge the application: a new pair is chosen and persisted, one line names the application and both pairs, and the heartbeat publishes the move as the serving change it is. A range with fewer than two ports left is `placement-unavailable` naming the range. The choosing is pure (`core/placement/ports.ts`, given the range, the held and quarantined ports, a random source and a free-port predicate); the files and the socket live behind the runtime driver, whose `ports(application)` a start action asks — a plan names the application and carries no ports.
- Run one application-owned process per assigned Scafo node. The supervisor id of that process is the application's name. Celld adopts deployments; retirement or reassignment stops the process. Each deployment a deploy produces is recorded immutably at `_scafo/deployments/<name>/<version>.json`, under the version Celld assigned and nothing else. THE DAEMON NEVER REWRITES OR PARSES THE ARTIFACT'S CONFIG: it locates `wrangler.jsonc`, then `wrangler.json`, at the archive root, refuses an artifact carrying neither with `invalid-input`, and hands that path to `celld deploy --config` untouched, so what the runtime reads is byte for byte what was uploaded. Application configuration is the application's. `scafo deploy --var KEY:VALUE` is the one edit, made client-side before the directory is packed: it is repeatable, splits at the first colon, refuses a name given twice, overrides same-named entries of the config's own `vars`, and goes into the archive only — the project directory is read and never written. `--no-bundle` sets `no_bundle` the same way. With neither flag the archive carries the config as it is. `--name` and `--env` never edit it either: they choose the application, and the config's own `name` reaches Celld as written.
- READY IS A PROCESS THAT ANSWERED FOR ITSELF, AND UPTIME IS NOT READINESS. After a start, each reconcile pass asks the runtime driver (`ready(application)`, behind the same seam `reload` uses — the node's own dial host and the process's PUBLIC port, `GET /.well-known/celld/health`, bounded to 2s, any 2xx yes, anything else or a timeout no) of every process that has not answered yet, and NEVER AGAIN of one that has: a ready run is trusted until it exits. There is NO continuous liveness checking and no liveness threshold anywhere; a probe costs one loopback request per not-yet-ready process per pass and nothing for a ready one, and never a bucket read. ONLY A READY PROCESS IS PUBLISHED in the node record's `serving`, which closes the gap on every first start and every restart where a port was routed before anything listened; what a node RUNS is `reconcile.processes`, what ANSWERS is `serving`, and becoming ready IS the serving change that beats and mints the hint.
- SCAFO REPORTS A FAILING RUNTIME PROCESS AND NEVER REPAIRS CELLD'S STATE. The supervisor pipes each process's stderr (forwarding it to the daemon's own), and a node keeps in memory, per supervised process, when it started, whether the run now going has become ready, the exits behind it and the last 5 stderr lines it wrote — escapes stripped, cut to 300 characters, quoted and NEVER parsed. `core/placement/process-health.ts` decides `crash-looping` from those alone, with no clock at all: 3 exits IN A ROW, the current run included, of runs that NEVER BECAME READY — a streak and not a time window, because the restart backoff slows a loop to about one exit every seventy seconds and a loop must not read as healthy for having slowed, and readiness and not duration, because a process that spends a minute retrying an unreadable node lease and then exits 1 is the same failure every time however long it stayed up. A run that became ready ends the streak, a run that is ready now means recovered, and the restart backoff — jittered, from 5s (the reconcile interval, which is what it used to hammer at) to 60s — resets only after a run that was ready. The health words are `starting` (running, not ready yet), `running` (ready) and `crash-looping`. A crash-looping process is still restarted but is NOT published in `serving`, because the routing every ingress reads must name only processes that answer. It is published instead as `failing: {<application>: {since, restarts, lastError}}` on the same beat, which is a serving-relevant change and mints the hint as one, so `scafo fleet nodes` reads `degraded` and `scafo app show` says `serving on N of M nodes` with the failing node's last error — straight out of the bucket, without asking the node that is failing. A process that is `starting` for a long time WITHOUT exiting is not a crash loop and is not reported as failing — no verdict was reached about it — and is not published either. `GET /v1/state` carries `ready` and `readyAt` per process beside the whole tail, the exits and the restart deadline; one log line says a process began crash-looping and one says it is answering again, never one per restart. The single exception to "never repairs" is `scafo app lease`, which an operator runs by hand: it reads what LIST, HEAD and GET each say about `fleets/<app>/nodes/<node>.json` — Celld's node lease, whose corruption wedges every restart of that process on the same key — and drops ONE such key on their word. It is bucket-direct, pinned and gated exactly as `scafo deployment prune` is, refuses a `held` lease with `reference-held` unless forced, re-reads the key after deleting it, and warns on every run that it will be removed once Celld recovers such a lease itself.
- Publish only routes backed by running processes and the optional platform API apex. NO WILDCARD UNDER A PLATFORM DOMAIN: every host there is rendered from an application's name, and a request for one nothing serves is answered by the ingress, never by a fallback application. A CUSTOM DOMAIN MAY CARRY ONE, because it is the operator's own name: `scafo app domain add <host> --wildcard` sets `wildcard: true` on the claim (nobody ever types a `*`, re-adding without the flag never downgrades it) and covers exactly one label below the host, as a TLS wildcard does. `<host>` answers from the application, `<X>.<host>` from `<name>-<X>` when the installation serves one, and every other single-label subdomain from the application itself; a deeper name matches nothing. Rules one and two render as ordinary host entries and the third as ONE `*.<host>` entry—a consumer looks a host up exactly first and, failing that, replaces its first label with `*` and looks that up once—which keeps the document `v: 1` and purely additive. Traefik renders it as a `HostRegexp` router at `WILDCARD_PRIORITY`, below every exact `Host` router. `--wildcard` takes a key whose scope reaches `<name>-*`; a host one label under a wildcard base may be claimed exactly only by that application or its own `<name>-…` family, and both halves refuse with `reference-held` naming the holder only to a caller whose scope reaches it. THE ROUTING DOCUMENT IS WHAT AN INGRESS APPROVES CERTIFICATES FROM (Caddy's `tls.permission.scafo` approves a host only when a fleet's document names it exactly, never through a `*.` entry), so it names exactly the hosts that may get one: the base and a subdomain that names a serving application, and NEVER an arbitrary one—the `*.` entry exists for routing, not issuance, because on-demand issuance per unknown name would burn the CA's weekly limit for the customer's domain, so those names need a wildcard certificate the operator obtains through DNS-01. Every ingress pulls: nothing is pushed into one. A node serves the fleet's routing at `/v1/ingress/routes`, generic or in a format an ingress speaks natively (`/v1/ingress/routes/traefik`); Caddy reads it through the `scafo` dynamic-upstreams module and Traefik through its http provider. That document also carries an optional `wildcards`: the sorted, de-duplicated bases this installation wants a `*.BASE` certificate for — every platform domain, and the base of every `*.<host>` entry the same render published — derived from the one host resolver, still `v: 1` and purely additive, so a consumer that ignores it behaves as before. Told `ingress.traefikCertResolver`, the Traefik rendering writes `tls: {certResolver}` on EVERY router, with `tls.domains: [{main: BASE, sans: ["*.BASE"]}]` wherever one of those bases covers the router's host, which is both how one wildcard certificate serves a whole base and the only way a `HostRegexp` router gets a certificate at all; the API denial carries the same `tls` as the API route it guards, because a router without one matches plain HTTP alone and would stand aside on the TLS entryPoint. Told `ingress.acmeDelegation`, Scafo only SAYS it — the claim routes answer with it, and `scafo app domain add --wildcard` resolves `_acme-challenge.<base>`, reports `acmeDns` and names the exact CNAME to create in place of the standing wildcard-certificate warning; it never refuses. Before a node's first reconcile pass has finished, both routes refuse with `ScafoError("draining")`—503—rather than serving an empty document: nothing deployed is an answer a poller acts on, and a node that has just booted does not have one. Operator configuration is the ingress's own and Scafo never rewrites it.
- Deny `/v1/storage` and `/v1/ingress/routes` at the public API apex, matched at a path-segment boundary, and the ingress must enforce that itself rather than trust the daemon behind it. Both surfaces are behind the ingress bearer token, which is the only credential an ingress holds.
- Observability is opt-in: events and access counters are ZSTD Parquet in the bucket; `scafo metrics` and `scafo traces` read them.
- `scafo deployment prune` deletes an application's old Celld deployments (`deploy/<script>/<version>/` and the Scafo deployment record), never a version a Celld pointer names; a pointer that moves onto a selected deployment refuses it as `cas-conflict`. It keeps the newest `--keep` (default 10) and deletes only what is ALSO older than `--older-than` (default 24h) — both gates are always weighed, and `0` lifts the one it is given to. It then collects `deploy-blobs/`: a shared asset blob no kept deployment's `assets.json` references goes once it is older than the same window, after the deployments and without a re-read; an `assets.json` it cannot read refuses the plan as `store-nonconforming`. The saved container images under `deploy/images/` are collected the same way, against the image references (`containers[].image`, `fence_image`) in every kept deployment's `manifest.json`, and a reference that is not one Celld writes likewise refuses the plan. Prune weighs only what Celld wrote as a deployment — `<script>/<version>/` in Celld's own shapes, a script name it accepts and a hexadecimal version id — and leaves everything else beneath `deploy/` where it is, its `images/` and `queues/` keyspaces (a queue's consumer attachment) above all. `--older-than 0` lifts that protection too, and prune warns that a deploy in flight uploads its blobs before it is visible. A real run prints the plan, then asks at the terminal before it deletes; `--yes` answers ahead of the question, and a run whose input is not a terminal refuses with `invalid-input` rather than take silence for consent. Because it is the one place Scafo reads Celld's own bucket formats, prune is PINNED to the Celld releases this build was verified against: it refuses to plan at all — `--dry-run` included — with `capability-missing`, and there is no override. Every node of the installation still answering (the liveness rule the version-skew gate uses) must report a verified `versions.celld`; an answering node naming no version refuses, nothing answering refuses, and a node that stopped answering is ignored so a retired machine's record cannot block prune forever. Every manifest it lists, kept and deleted alike, must carry a `schema_version` (absent means 1) and `required_features` that build knows, and every `assets.json` it reads a known `schema_version`; a manifest present but unreadable refuses, while a version directory with no manifest at all is a deploy in flight — Celld writes the manifest after the files and before the pointers — and keeps the age-window semantics. `src/core/registry/_celld-contract.ts` holds that contract, every constant permalinked to the upstream lines it mirrors at the commit of a tag, with the procedure for adding a release. The command is unstable until Celld has a deployment lifecycle of its own and warns on every run. CLI warnings go to stderr as `scafo: warning: …`; `SCAFO_SILENCE_WARNINGS=1` silences all of them.
- `_scafo/freeze.json` is the fleet's deploy freeze, set by an ADMIN through `scafo fleet freeze` and lifted by `scafo fleet unfreeze`; its absence means deploys are taken. While it stands, every node refuses deploy intake with `deploys-frozen` (409) before anything is created, and the refusal names when, by whom, why and how it is lifted. It touches nothing else: serving, reconciliation, retirement and `scafo app delete` all carry on, and the first admin's record — stamp and reason — is the one that stands if it is set twice.
- Retiring stops serving and is reversible for the length of a 24h grace; deleting is refused until the grace has run out or `--force` is given, and it removes EVERYTHING of the application — record, trust policy, deployments, deploys, placement, domain claims and the whole `fleets/<name>/` prefix. Blocking is the admin's reversible full stop: `application-blocked` (409), nothing served, no certificates, no deploys, nothing deleted.
- CLI naming: commands address an application with `--name <name>` and optionally `--env <X>`, which addresses `<name>-<env>`; both halves and the join are names, and a join that is not one is `invalid-slug` naming both parts. One client-side resolver (`src/cli/_application.ts`) does it for every command. `scafo deploy` reads `name` from the project directory's `wrangler.jsonc`/`wrangler.json` when `--name` is absent, and never writes it back. Operator scope is `--apps a --apps shop-*`. `scafo app domain add <host>` / `remove <host>` / `list` reach a node or the bucket like their sibling setters; after a successful `add` the CLI resolves the host and the application's platform hosts (bounded, injected resolver, never a refusal) and either says DNS already points here or warns—`scafo: warning: …`—that it does not yet, `--json` carrying that as `dns: ok|pending|unknown`. `--wildcard` (on `add` alone) additionally resolves `scafo-dns-check.<host>`, reports it as `wildcardDns`, and warns what the ingress still needs; `domain list` and `app show` mark a wildcard claim, and the record mirrors it as `wildcardDomains`, a subset of `domains`.
- Scafo API and Celld peer listeners default to loopback. Widen only through an explicit private-network or WireGuard decision.

## Packaging

- `patches/citty@0.2.2.patch`, registered under `patchedDependencies` in `pnpm-workspace.yaml`, adds citty's `multiple: true` argument modifier, which `scafo deploy --var` needs to see every occurrence of a repeated flag rather than only the last. It mirrors unjs/citty#259; drop it, potentially unchanged, once citty releases the feature. Anything that installs dependencies has to carry `patches/` with the manifest and the lockfile. citty is a pinned dev dependency bundled into `dist`, never an external import, so every distribution of the CLI runs the patched parser.
- The image runs as uid 10001 with Celld 0.5.1 and esbuild. Its direct Node entrypoint stays PID 1 in a private PID namespace.
- EVERY RECIPE KEEPS THE STATE DIRECTORY (`SCAFO_STATE_DIR`, `/var/lib/scafo` in the image) ON STORAGE THAT SURVIVES A CONTAINER RE-CREATION, not only a restart, because the runtime work directories above live under it. Compose, Coolify, Dokploy and both playgrounds use named volumes; k3s is a StatefulSet with a retained per-pod PVC and never an `emptyDir`; `scripts/install.sh` uses systemd `StateDirectory=scafo`, which `uninstall.sh` preserves without `--purge`; the VPS roll re-mints the tunnel keypair alone and leaves the rest of the directory. The image declares no `VOLUME`: an anonymous volume is not reattached to the next container either, so running with nothing mounted must look like what it is.
- Allow at least 50 seconds for node shutdown. Celld's default may take 40; Docker and Kubernetes grace periods must not be shorter. If `CELLD_SHUTDOWN_TOTAL_MS` is larger, give the enclosing grace at least 10 seconds more.
- WITH `--network host` THE RUNTIME PORT RANGE IS THE HOST'S. A node sharing the host's network namespace draws its pairs from the machine's own port space, where the machine's own services live — which is why the range is settable at both ends (`runtime.portRangeStart`/`runtime.portRangeEnd`) and why every port is bind-probed before it is used rather than assumed free.
- Caddy/Traefik share the node network namespace to reach loopback application processes. Multi-node Celld peer traffic needs a trusted wider bind.
- `scripts/install.sh` verifies every download before installation. `scripts/uninstall.sh` preserves `/var/lib/scafo` unless `--purge`; neither mutates the bucket.

## Conventions

- Every setting is readable from three places, with the same precedence everywhere — flag → environment → config file → default. The ones this design added: `registry.resyncIntervalMs` / `SCAFO_REGISTRY_RESYNC_MS` / `--registry-resync-ms` (60000), `registry.nodeRefreshIntervalMs` / `SCAFO_REGISTRY_NODE_REFRESH_MS` / `--registry-node-refresh-ms` (30000), `coordinator.leaseTtlMs` / `SCAFO_COORDINATOR_LEASE_TTL_MS` / `--coordinator-lease-ttl-ms` (45000, renewed at a third), `coordinator.reapIntervalMs` / `SCAFO_COORDINATOR_REAP_INTERVAL_MS` / `--coordinator-reap-interval-ms` (600000). Each is a positive safe integer and anything else is `invalid-input`. The runtime port range and its quarantine read the same way: `runtime.portRangeStart` / `SCAFO_PORT_RANGE_START` / `--port-range-start` (24000, below the ephemeral range so no outgoing connection ever holds a port of ours), `runtime.portRangeEnd` / `SCAFO_PORT_RANGE_END` / `--port-range-end` (the start plus 998, never past 65535), both within 1024-65535 and together holding at least two ports, and `runtime.portQuarantineMs` / `SCAFO_PORT_QUARANTINE_MS` / `--port-quarantine-ms` (600000). The two ingress settings that are about certificates read the same way and default to unset: `ingress.acmeDelegation` / `SCAFO_INGRESS_ACME_DELEGATION` / `--ingress-acme-delegation`, a host, and `ingress.traefikCertResolver` / `SCAFO_INGRESS_TRAEFIK_CERT_RESOLVER` / `--traefik-cert-resolver`, a name of up to 64 letters, digits, hyphens and underscores from Traefik's own static configuration; anything else is `invalid-input`. `scafo deploy` adds `--queue-timeout <seconds>` and `--no-wait`.
- A list is a REPEATED FLAG on the command line — each occurrence one whole value, nothing split on commas — comma-separated text in an environment variable, which cannot repeat, and a JSON array in the config file.
- ESM, modern TypeScript, explicit `.ts` relative imports; `isolatedDeclarations` requires annotations on exports.
- Prefer Web APIs in core. Use subject-first functions with an options object for multiple arguments. Errors are typed contracts with actionable details and original causes.
- Reuse existing mechanisms; keep modules focused. Prefer one short block comment at a hidden constraint; user docs describe current behavior, not history.

Specs and the decision log live outside this repository.
